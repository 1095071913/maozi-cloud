# 灰度开发模式

> 在本地开发中经常会发生只改了A服务接口 但由于改动的地方依赖了BCDE服务 从而需要启动BCDE服务才能进行接口测试，这让本地的内存或测试成本大大增加，为了解决这类问题引入了灰度开发模式 所谓的灰度开发模式其实就是 用一台机器公用来做部署所有的微服务作为基础服务，本地改了哪些服务就启动哪些服务作为灰度服务，根据客户端传递的标识来走灰度服务还是基础服务 若灰度服务不存在则走主服务

1. 确保基础服务和灰度服务的网络互通
2. Idea启动灰度服务时添加JVM参数`-Dapplication.version=maozi` maozi作为灰度标识，客户端需要传入该标识才能路由到灰度服务，默认值为main作为基础服务
3. 若基础服务和灰度服务都在同一台物理机时添加JVM参数`-Dapplication.port=0`和`-Dapplication.dubbo.port=-1`设置随机端口防止端口冲突
4. 由于`maozi-cloud-gateway-service`服务是入口，所以无法通过服务端灰度 也就是本地启动了`maozi-cloud-gateway-service`也无法被灰度调用
